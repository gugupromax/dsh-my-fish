# My Fish

DSH 中的本地陪伴角色与个人助理。**0.6.0 开发预览版**，包名 `dsh-my-fish`，MIT 许可。可以日常聊天、延续自己的兴趣，也保留按需办事的能力；角色、记忆与各渠道账号权限分别管理。

**仓库只提供通用角色模板。** 默认名称为 My Fish，称用户“你”，自称“我”，兴趣留空。个人名称、表达方式、人设和兴趣由使用者在本地工作区设置，不随源码上传。可直接使用或修改 [角色模板](docs/ROLE_TEMPLATE.md)。

适配已核实的 DSH `0.2.1-rc.3`。电脑或 DSH 停止运行时，计划不会继续执行。

## 本版功能

- **连续兴趣**：从一个好奇的问题开始，实际读到新资料后保存自己的看法、改主意的理由和还想弄清的问题，下次接着聊。
- **日常交流**：主会话保持原人设，闲聊优先自然回应，不默认拆成工作任务；可以表达不同看法，用户原话和角色判断分别保存。
- **一起聊 B站**：粘贴 BV 号或规范视频链接，交给同一个主会话实际读取简介和有限评论后讨论；不把元信息当作看过视频。
- **陪伴内容优先**：首屏显示“最近在琢磨”和“留给你的话”，想法变化与出处点击展开；工作区、计划与目标默认收起。详见 [陪伴与连续兴趣](docs/COMPANION.md)。
- **固定聊天**：账号区附近的 My Fish 入口始终打开同一个主会话；首次只初始化，不发送任务。
- **会话失效恢复**：每次打开先检查宿主记录；原会话已无有效记录时，人工点击会建立新的空会话，保留个人资料。临时故障不更换引用，创建结果不明时保留原请求核对，避免重复创建。
- **自定义工作区**：设置中填写新路径，保存后自动迁移全部助理数据和工作文件，逐文件校验，同一主会话继续使用；保留旧目录备份。
- **独立记忆**：按关键词和中文片段召回，保留来源、分类、有效期，可纠正和忘记；不是向量检索。
- **表达偏好**：快捷选择简短、自然或正式的回复，另行设置表情符号用量；默认跟随原人设，保存不改写人设正文。
- **临时免打扰**：可暂停自主跟进两小时或到今天结束，到期按原作息恢复；手动聊天和明确设置的定时计划照常使用。
- **临时记忆**：有效期可选长期、今天、本周或自定；纠正正文默认保留原期限，到期后不再召回。详见 [表达、免打扰与记忆有效期](docs/ASSISTANT_PREFERENCES.md)。
- **持久计划**：复用可选任务看板，支持周期/单次、修改时间、暂停、恢复、取消和运行记录；有变化才进入本地动态盒。
- **个人权限**：主会话及核对运行时归属的子孙使用宿主工具守卫；本机代码/命令、文件写、浏览器交互和委派默认关闭。
- **外发审核**：受控查询和社交适配器检查私密词、常见凭据及本机路径，拒绝时不回显命中内容。
- **可扩展渠道**：统一适配器注册与能力目录，目前接入 X 和 B 站只读能力，后续渠道可由独立插件注册。
- **紧凑渠道目录**：每个渠道默认收起，只显示名称和简短状态；点击后查看完整能力、连接及权限信息，新增渠道沿用此方式。
- **配置与检查合一**：展开X即可设置账号、接入方式和操作开关，保存后在同一区检查连接与身份；完整诊断信息放入次级“详细状态”。B站仍为匿名只读，可检查公共读取连通性。检查本地权限配置不等于已实测收藏或发布。
- **X**：原搜索、可见正文、浏览器时间线和受控写适配继续兼容，写开关默认关闭。
- **B 站**：搜索摘要、公开视频资料与简介、有限分页评论；匿名读取，不读取上游插件账号，不提供本版写操作。
- **官方听写衔接**：固定会话使用官方听写，识别文字先进入草稿；设置可只读检查服务状态。

尚未实现：回复朗读、连续语音、完整桌面控制、确定性本地脚本调度，以及 B 站收藏/点赞/发布、私信和其他未注册平台。

0.6.0 首先在现有主会话与 B站公开内容上实现连续互动，不安装 QQ/NapCat，也不声称接入了 QQ。自主探索仍需开启已有“允许助理主动跟进”，并遵守作息、次数和临时免打扰；升级不自动开启它。所有“读到过”的经历都来自实际成功读取回执。代码与隔离验证通过不等于模型拟人表现已长期验收。

B 站搜索使用当前会话开放的公共网页搜索，不等于站内完整搜索；读取资料和评论不等于已观看视频。渠道支持、运行就绪、账号核验和真实执行会分别展示。完整接口和新增渠道示例见 [渠道扩展](docs/CHANNELS.md)。

## 安装与升级

需要 Node.js 22+ 和兼容 DSH。仅用聊天/记忆/计划不需 X 或 Python；X 浏览器模式额外使用已装 Chrome 和项目依赖 playwright-core，不下载浏览器。

源码仓库：[gugupromax/dsh-my-fish](https://github.com/gugupromax/dsh-my-fish)。可克隆仓库或下载源码包。

克隆源码、进入项目目录，退出 DSH 后执行；使用源码包时直接进入解压后的目录：

```powershell
git clone https://github.com/gugupromax/dsh-my-fish.git
cd dsh-my-fish
node scripts/install-local.mjs --app '<DSH 应用完整路径>'
```

旧版升级先审阅再执行：

```powershell
node scripts/install-local.mjs --dry-run --migrate-legacy --app '<DSH 应用完整路径>'
node scripts/install-local.mjs --migrate-legacy --app '<DSH 应用完整路径>'
```

默认 profile 为 desktop。使用本地 link 安装后须保留源码目录。安装器只准备本项目依赖，通过宿主 CLI 替换旧依赖，不复制用户数据或安装全局包。重开 DSH 后进入侧栏 **My Fish** 或 **设置 → My Fish**。详见 [升级指南](docs/UPGRADE_MY_FISH.md)。

如果曾删除个人主会话，更新后重新加载 DSH 后端，再点击 My Fish 即可建立新空会话。被删聊天不能由插件恢复，独立记忆/配置/工作文件保留。恢复不会自动重发旧任务；原自主跟进若已启用会暂缓，可在设置中单独“恢复自主跟进”，不会解除账号限流或不确定写入锁。

## 计划与权限

持久计划需要提供 taskBoard 服务的兼容任务看板；本机核对过 `@linxin666/dsh-client-ui-task-board` 0.4.8。未安装时界面明确提示，聊天/记忆仍可使用。

固定主会话可通过 assistant_plan 管理明确时间、时区、来源及判断条件，也可在设置中添加每小时整点、每天或单次计划。计划独立只读执行，不继承主会话的私有记录和社交写权限，通过 assistant_plan_report 回到本地动态盒。宿主负责真实执行状态；已保存不等于已完成。运行中不重叠启动，错过不补跑。

没有 X 账号时可用宿主开放的 web_search/web_fetch。工具存在不代表当前预设可见或服务连接正常。

本版推荐**原生工具调用模式**。PTC 的 run_code 可以直接调用 Node，因此归入本机代码/命令权限，默认拒绝；只读计划也不开放。仅使用 PTC 的预设可能无法查询，需改用原生工具预设。

允许代码/命令或浏览器交互后，它们可能间接对外操作，插件不能保证拦截其中全部社交写入；宿主目录范围和审批始终适用。详见 [权限边界](docs/PERMISSIONS.md)。

## 数据

新安装默认 `<DSH_HOME>/my-fish`，未设 DSH_HOME 时为当前用户的 `.dsh/my-fish`。设置 → My Fish → 工作区中可改为自定义绝对路径，点击“保存并迁移工作区”。新路径需不存在或为空，父文件夹需已存在；运行中的任务须先停止。迁移校验失败会保留原数据，未完成事务在重启时检查恢复。

自定义位置由宿主目录中的 `my-fish-location.json` 保存，重启后继续使用。没有自定义定位时沿用新目录优先/旧 x-whale 原位兼容规则，不自动合并。

迁移保留原主会话并切换实际工作目录，但**不会改变 DSH 原会话的文件权限根或项目归属**；新位置的命令/文件操作仍可能被宿主拒绝或要求审批。DSH 聊天和任务看板账本仍由宿主管理，插件源码/安装目录不随之移动。详见 [工作区迁移](docs/WORKSPACE.md)。

个人角色设定、账号、加密凭据、主会话、记忆、目标及动态保留在本地工作区，不进入源码或公开发行包。升级保留已经保存的本地角色，不会用公共模板覆盖。Windows Cookie 使用当前用户 DPAPI；忘记记忆不删除旧聊天和日记。

## 开发与发行

```powershell
npm ci --ignore-scripts
npm run check
node scripts/verify-installed.mjs
npm run stage
```

安装版验证仅适用于装有兼容 DSH 的机器，使用合成数据，不启动 GUI 或模型。其他环境运行 npm run check，缺少宿主时相应源码契约检查自动跳过。

`dist/dsh-my-fish` 是公开发行的源码暂存目录，含通用模板、测试、文档和 PUBLIC_FILES.json；排除个人角色、依赖环境、用户数据、recovery 和旧发行包。发布前仍须审查最终文件清单；生成该目录本身不会上传 GitHub。

参阅 [验证](VALIDATION.md)、[交接](HANDOFF.md)、[需求](docs/REQUIREMENTS.md)。
