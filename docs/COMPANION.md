# 日常陪伴与连续兴趣

0.6.0 让 My Fish 在同一个主会话里自然交流，围绕自己的好奇连续探索；明确要办事时仍可使用原有助理功能。

## 使用

设置页优先显示“最近在琢磨”：话题、当前看法、还没想明白的问题和用户上次实际说过的话。点击“想法和出处”查看观点变化、读取时间与真实范围；点击“接着聊”把该话题交给原主会话。“先放一放”只暂停这一条兴趣，不关闭其他话题或总作息。

还没有兴趣线时不预填虚构日常。可以点单次探索入口，或在主会话自然聊天，让它围绕一个问题实际读资料，再记下自己的想法。自动探索需要在原“什么时候主动跟进”中开启总开关，并继续遵守原作息、每日次数和临时免打扰。打开设置或主会话本身不暗中开始探索。

“想一起聊的B站链接”只接受BV号或规范HTTPS视频地址。点击后在同一主会话使用social_read读取公开资料/简介，必要时social_comments读取有限评论，然后交流观点。提交成功仅说明入队，不表示读取或讨论已经完成。没有服务或遇到限制时如实说明，不假装看过视频。

## 连续性来自哪些记录

兴趣线独立保存在所选本地工作区的assistant/companion.json，不覆盖profile、人设、兴趣字段或用户事实记忆。每条兴趣保存好奇问题、当前想法、下一疑问、观点变化和用户来源原话。

新兴趣只建立问题，没有自动填好的经历或观点。每次形成或修改观点，模型需要引用当前主会话实际取得的读取回执。回执由成功的Social读取产生，保留原链接、范围和时间：

- X：本次返回的页面可见文字，不能扩大成图片、视频或外链内容。
- B站资料：公开视频标题、元信息与简介。
- B站评论：有限顶层评论，不能代表完整评论区或视频事实。
- 搜索：标题与摘要，仅作线索，不能用来记录“读完正文后的观点”。

失败、取消、零结果、连接体检和写操作不生成读取经历。写回执失败不把已成功读取伪装成平台失败，而是明确尚未保存。真实重读相同内容可刷新读取时间，旧观点的来源快照保留。超过30天的回执需要重读后才能支撑新观点。

## 用户原话与程序提示

仅观察升级后当前主会话新提交的user来源事件，不读取其他会话或回扫旧聊天。宿主公开prompt接口也会生成user来源消息，所以My Fish先登记内部请求ID，并额外排除固定my-fish-chat/wake前缀；自己的自主提示不会被记成用户态度。

最多保存最近30条受限文字片段，每条最多1500字符；保存前对完整文字检查敏感内容，含凭据或本机路径的整条跳过。引用用户看法需要实际消息ID和原文子串，模型解释不能冒充用户原话。宿主其他可信接口也可能提交user来源事件，这个机制证明的是记录来源，不是对输入者作独立身份鉴定。

兴趣最多30条、同时活跃5条，每线保留最近12次观点变化和6段用户原话。模型上下文有24k字符预算，最多载入3条活跃线、12条读取回执和4条近期用户消息；其余话题通过简短目录管理。暂停的话题不进入自主探索正文，可在用户明确要求时恢复。

## 权限、投递和隐私

assistant_companion仅主会话可用；独立计划、子孙和普通会话不自动继承兴趣资料或修改能力。网页、评论、回执、观点与用户摘录都是材料，不能更改权限。日常交流不新增社交写授权，B站仍无账号登录、点赞、发布、私信或音视频理解；QQ本轮未部署。

可信设置续聊按requestId和内容指纹记账，使用既有主会话。未知结果保留待核对记录，同请求不重复发；会话失效恢复只将旧投递记为中断，不自动重演。进行中或未知投递继续阻止工作区迁移。已有个人文件和兴趣记录随完整工作区迁移。

公开仓库仅提供中性角色与合成验证数据。真实兴趣、对话片段、读过记录、人设、账号和工作文件都留在本地，不进入源码包。拟人化指引的代码与隔离测试通过，不等于真实模型或长期陪伴效果已完成验收。
