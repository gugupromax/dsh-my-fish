# 固定会话与宿主工作区分组

0.6.1 将“个人资料存放位置”和“DSH工作区中的固定聊天”分别展示。改变文件工作目录不等于把聊天放进宿主分组。

## 选择已有会话

在设置 → My Fish → 工作区中选择聊天所在的宿主分组，再选择该组已有会话，点击“固定使用这条会话”。只有一个有效候选时预选；有多个时需明确选择。目录只来自宿主工作区和会话header元数据，不扫描聊天正文。

绑定不创建会话、不发送消息、不调用模型，也不合并或删除旧聊天。原角色、记忆、目标、兴趣、账号锁、次数和作息保留；旧主会话退役审计保留，新的主会话获得原个人工具门禁保护。已经保存的外部操作开关不因换会话而开启。

旧主会话、所选会话或其活跃子任务在运行时，或有未知投递、创建/外部操作未确认时，不切换绑定。等结束并核对后再操作，插件不会擅自停止任务。

绑定后，侧栏My Fish、聊天按钮、兴趣续聊、B站共聊、手动唤醒和自主探索都复用同一个会话ID。只打开聊天不会投递任务；探索/续聊仍须明确点击或沿用已授权作息。已存在的独立只读定时计划保持其既有执行方式，不改成主会话中的聊天。

## 首次创建与旧会话分组

首次明确初始化时，先解析或注册真实宿主工作区，再调用sessionController.create({sessionId,workspaceId})。宿主用工作区路径创建并附加分组，插件保存实际返回ID。后续只核验存在性与分组，再打开或prompt；不反复调用create。

真实宿主的create({sessionId})不是“继续已有聊天”接口：已有turn的会话可能生成另一个ID。只传cwd也不会自动归组。0.6.1使用真实SDK隔离回归覆盖了这两个差异。

已有未分组主会话的原始header.cwd若与目标分组路径相同，可直接attachSession保持ID与历史。路径不同则不能通过改effective cwd或篡改header硬挂组，应选择目标组已有会话。插件不会为了分组偷偷创建替代会话。

## 读取失败与文件迁移

工作区或元数据服务未就绪、临时IO错误、目录失效不能被解释成删除或新建许可。目录失败时显示上次记录与明确提示，保留所有表单草稿，不宣称新绑定已确认。无关失效旧分组不会阻断当前有效分组。

全新数据根的只读查询不落盘；首次明确创建才初始化目录。曾存在而后丢失的根目录、已配置定位文件指向的丢失目录仍拒绝，防止产生空白替代资料。

完整助理数据迁移仍保留同一主会话。已有会话的immutable header.cwd、宿主分组和权限根不会随effective cwd自动改变；原分组绑定以实际宿主记录为准。选择另一条已有会话是明确的绑定操作，不能冒充旧聊天已迁入或被合并。
