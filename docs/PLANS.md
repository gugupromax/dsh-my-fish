# My Fish 计划桥接

0.4.0 增加对 DSH `taskBoard` 公共服务的计划管理适配。My Fish 不增加第二个 cron 定时器，不读写任务看板的真实账本文件；宿主插件负责保存规则、计算下一次触发、执行、权限门禁、运行历史和恢复。

## 可以做什么

- 创建明确时区的五段 cron 周期计划，或指定未来时间的一次性计划。
- 查看 My Fish 创建的计划、当前实际指令、内容能否编辑及限制原因、下一次触发、宿主运行历史及本地汇报回执。
- 首次执行前单独修改标题或指令，保留原计划标识、时间规则、权限和创建请求审计。
- 暂停未来触发、恢复、修改计划时间、取消并归档，保留原运行历史。
- 由计划独立执行会话汇报本轮；无变化时安静记录，有实质变化时写入本地动态盒，并复用动态盒原有链接去重。

任务看板未安装、未启用、服务不可用或返回格式不兼容时，界面明确显示不可用；没有其他隐藏调度器替代它，也不会声称已经保存或执行。

## 主会话和执行会话

0.6.5固定`mode: dsh-my-fish-plan-native`。这里的mode是代理预设ID，不是工具模式本身；宿主standard预设没有显式覆盖工具展示时也可能继承PTC，不能靠名称判断。插件通过agentPresets公开注册独立预设，明确使用native展示、时间上下文、只读文件和网页模块，并通过公共tools.restrict隐藏已知全局个人/写工具。其他未知工具仍受守卫拒绝，不因此授权脚本、任意命令或社交写入。

创建前必须ensureReady确认注册及resolve成功，失败不保存卡片、不退回默认PTC。服务连接后启动修复仅对本插件普通旧卡片发送公开`update {patch:{mode}}`，不改正文/规则/权限或新建计划。卡片有续接/交接资料、父子关系或执行权限/复用方式改变时blocked，避免原生更新清除资料或宿主强制预设覆盖；修复结果可在主会话`assistant_plan {action:'repair_runtime',requestId,id?}`核对，不填id核对全部本插件计划。已有旧执行会话不会更换其已锁定预设，也不会补跑。

列表的agentPreset/requiredPreset/requiresRuntimeRepair/runtimeRepairBlocked区分卡片配置与限制，不把卡片字段当作真实模型已经执行。assistant_capabilities.nativePlans只给公开预设和修复计数；runtime给实际加载版本。正常主会话与全局默认工具模式不被改变。
个人主会话负责接受用户意图和管理计划。定时计划通过任务看板启动**独立只读会话**，不会重新创建或覆盖个人主会话，也不会把旧 `reuseSession` 错认成“固定进入个人主会话”。创建时明确固定 `permission: read-only`、`goalRun: false`、`reuseSession: false`、`applyCardDefaults: false`，并且不采纳看板上可能更宽的“新卡片默认权限”。兼容 0.4.8 与 0.4.11 的共同创建字段：省略 `teamRun`；0.4.8 只有显式 `true` 才开启团队模式，0.4.11 已移除此创建字段并拒绝未知字段。没有向执行提示中自动复制用户个人记忆或角色正文。

公开文档和示例只使用 [通用角色模板](ROLE_TEMPLATE.md) 与合成计划。使用者的个人角色、兴趣和实际计划保留为本地运行数据，不属于公开源码包。

计划运行会话不因此得到主会话的社交发布、收藏、回复、公开 @、个人记忆写入或脚本执行权限。模型提示本身不构成技术隔离；实际调用还需经过 My Fish 个人/计划作用域守卫和 DSH 宿主权限。子 agent 的归属覆盖仍须单独验证，不能从单会话验证推断整个 agent 树都被隔离。

计划独立会话结束前调用 `assistant_plan_report`。适配器从宿主快照中的真实执行记录推导本轮执行标识，要求调用会话与该计划当前未结束执行的 `sessionId` 一致。模型填写一个计划或执行标识不能取得权限。允许同一执行的相同回执重试，内容不同的重复汇报会被拒绝。

该报告只记录本地消息和回执，**不直接把宿主执行标为成功**。实际完成、失败、取消仍由看板自己的会话观察与验收决定。“有通知”“模型汇报”“宿主已结束执行”是分别可检查的状态。

## 时间与恢复

- 所有创建与修改必须提供可由本机解析的 IANA 时区，例如 `Asia/Shanghai`、`UTC`；不接受有歧义的 `CST`。
- 周期规则使用五段 cron：分钟、小时、日、月、星期。范围和步长先在本插件检查；真正的下次时间和不可达日期由任务看板最终校验。
- “每小时整点”与“从现在起每 60 分钟”不等价。界面明确提供整点选项；模型将自然语言转换为规则时应把实际语义说明白，不用探索作息和每日次数替代它。
- 一次性时间是 UTC epoch 毫秒，创建或重新启用时必须在未来。输入界面按显示的本机时间换算；其他时区的规则要显式填写。
- 沿用已装任务看板行为：宿主退出、电脑关机/睡眠期间不执行，错过不补跑。循环任务推进到下一个未来时点；过时的一次性任务停止为 `missed`。
- 同卡已有未结束执行时，看板跳过该次触发，不叠加运行；这是看板的调度门禁，不是本插件额外计时器。
- 暂停只停止未来触发，不会终止已经运行的会话。运行中的计划不能被归档成“已取消”；先暂停未来触发，再到宿主停止本轮后取消。
- 沿用看板的恢复语义：从禁用重新启用规则会重置其次数预算。若配置了 `maxRuns`，恢复相当于启用一轮新的预算，界面和返回说明不能把它描述为继续原有剩余额度。

## 修改和幂等

0.6.2修复`assistant_plan`返回`value is not lossless JSON`：看板内存快照的schedule含有自有undefined可选属性，原桥接structuredClone会保留这些值；工具SDK在render之前拒绝回执，因而可能先保存成功再报错。现在只投影公开时间、计数及停止/跳过元数据，省略未设置字段；部分旧报告同样省略缺失事实，不把未知通知状态补成false。没有全局JSON序列化清洗，也不改宿主计划内容或权限。

升级后先用list核对原计划；看到旧错误不能认定没有生效，也不能据此用新请求标识重复创建。正常操作通过公共taskBoard服务完成，不以直接改账本作为替代管理通道。计划已启用和有下一次触发只表示调度已安排，实际执行仍以宿主运行记录为准。

创建需要稳定的 `requestId`，任务 ID 由该请求确定。相同请求、内容、来源会话重试返回原卡片，不重复创建、不重新启用已经结束或取消的规则。即使第一次响应丢失，重新打开适配器后仍可通过相同请求找到同一卡片。相同请求改了内容或来源则拒绝。

管理动作通过任务看板的公开 `apply(requestId, action, initiator)`，保留看板自己的幂等记录和所有原生门禁。结果未确认时应保留同一请求标识核对或重试，不生成新标识反复提交。

0.6.3之前的update仅支持时间，传入title或instruction会在本地白名单直接报“计划管理格式或字段无效”；这不是宿主已把原计划改坏。现在update支持单独title/instruction或完整schedule，必须同时提供稳定requestId与计划标识。id、taskId、planId在工具Schema和API中统一可用，多个别名必须一致；缺少字段会给出可操作的提示。

修改内容仅在首次执行前允许。存在任何执行记录（正在运行、已结束，或启动前取消）即按宿主规则冻结；list提供canEditContent和contentEditReason。冻结后仍可改时间，不自动取消或重建。已有宿主freeze/handover资料时拒绝内容编辑，避免原生更新的缺省清除行为损坏续接资料。提示被其他入口改成未知模板时不恢复旧正文，list的instruction为null并解释限制，时间仍可管理。

内容修改只发原生`{kind:'update',taskId,patch:{title?,prompt?}}`。原始integrations标记和fingerprint保留创建时的审计及幂等身份；当前正文从实际prompt严格匹配My Fish只读模板后提取，不能继续展示旧marker.instruction。原创建请求重试只返回当前卡片，不撤销后来的编辑；内容更新已提交但回执丢失时，相同内容重试返回unchanged，不重投，即使此时已有执行记录。与请求一致只能证明当前保存值一致，不能冒充已查到某次请求的历史回执。

看板没有内容与时间的原子混合动作。两者都实际改变时，桥接在任何写入前拒绝，要求分两次update；原样回传且没改变的字段可以作为回显，实际只写改变的一类。不会先改正文再因时间失败而留下半成功。

修改时间未显式填写enabled时保持原启用/暂停状态，不会自动恢复；周期规则未显式填写maxRuns时保留原上限。切换为一次性规则时按宿主语义移除周期上限，使用隐含的一次预算。只改内容不重算nextRunAt或次数预算；完全相同的内容/规则请求为无操作。

取消使用原生 `archive`，保留卡片和执行历史，不直接删除账本行。My Fish 的清单仅返回带本插件集成标记的卡片，管理操作不能改动其他来源的普通看板卡片。

## 集成接口

```js
const plans = new Plans({
  getHost: () => taskBoardService,
  assistant, // AssistantStore：复用本地动态盒与链接去重
  store,     // Store：保存 planReports 本地回执，最多 100 条
});

plans.list();
await plans.create({
  requestId, title, instruction,
  schedule: { mode: 'cron', cron, timeZone, maxRuns },
}, callingSessionId);

await plans.manage({
  requestId, id,
  action: 'pause', // 或 resume / cancel / update
  // update 时提供完整 schedule
}, callingSessionId);

// 仅首次执行前；不需要携带schedule或其他未修改字段。
await plans.manage({
  action: 'update', id, requestId: newStableRequestId,
  instruction: '修改后的明确只读任务要求',
}, callingSessionId);

await plans.report({ id, notify: false, summary }, executionContext);
plans.isPlanSession(executionContext);
```

`id` 的管理和报告别名兼容 `taskId`、`planId`；管理同时传多个标识时必须一致。调用者必须在桥接外对创建/管理执行主会话校验，设置页则仍走受信本机请求检查。`report` 自己校验真实计划执行来源，不依赖外层把它当成主会话。设置页本版仍以原来的修改时间入口为主，新增内容编辑通过主会话assistant_plan工具使用。

## 验证证据与限制

新增 14 项模块测试，覆盖服务缺失、规则和时区、创建形状、响应丢失后的幂等、一次性已结束后的重试、暂停/恢复/修改/取消、改时间保留暂停和次数上限、其他卡片隔离、运行中的取消拒绝、真实执行来源检查、安静汇报、重复通知和回执存储失败。另有 5 项完整插件接线测试，覆盖实际 UI 请求形状、主/普通/计划会话隔离、计划子代只读、可选 taskBoard/agents 服务后续接入、新旧受信 API 和修改时间保留原指令。

本机还通过已安装任务看板的纯源码契约验证：真实 `parseActionEnvelope` 接受桥接产生的 create/set-schedule/archive；真实 `applySetSchedule` 保存明确时区、算出下一个整点，并拒绝不可达日期。测试仅将公开程序源码复制到隔离临时目录转换 TypeScript 后调用纯函数，结束后清理，没有读取真实任务正文、创建真实计划、启动宿主、执行脚本或访问账号。

上述证据不是已安装 GUI、真实计时器、模型计划执行或跨重启验收。发行前的真实运行验收仍应逐项记录；示例规则不是创建真实计划的授权。
