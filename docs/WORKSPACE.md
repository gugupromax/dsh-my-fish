# 自定义工作区与自动迁移

0.4.1 在 **设置 → My Fish → 工作区** 中支持自定义完整资料位置。此设置不移动插件源码、安装链接、DSH 会话库或任务看板账本。

## 使用

1. 停止正在执行的个人任务和计划，等待正在进行的操作结束。
2. 输入本机完整绝对路径。父文件夹须存在；目标本身可以不存在或是空目录。
3. 点击“保存并迁移工作区”。界面显示迁移中并暂时禁用其他操作；成功后显示新资料位置和实际工作目录。

迁移包括角色、记忆、目标、消息盒、权限与私密词、账号配置、原字节加密凭据、状态/轮次回执、旧日记和 workspace 工作文件。主会话标识不变，重启后继续使用新目录；不自动创建或执行任务。

这些内容属于本地运行数据，不随源码上传 GitHub。公开仓库仅提供 [通用角色模板](ROLE_TEMPLATE.md)；本地迁移和保留备份不代表授权公开个人设定或工作文件。

同一台电脑和 Windows 用户的 DPAPI 文件不解密、不回显，仅原样复制；这不是跨用户/电脑的凭据迁移工具。

## 提交与恢复

旧目录始终保留为备份，不自动删除。目标非空、嵌套/重叠目录、盘符或宿主主目录、源码目录、junction/符号链接/重解析点会被拒绝，避免覆盖或越界。

流程在私有临时目录复制，逐文件核对路径集合、长度和 SHA256，再复核来源没有变更。只有核验通过、宿主接受实际工作目录后，才提交稳定定位。当前事务所持运行锁经过归属核验，不作为数据复制；未知锁不能忽略。

稳定文件位于 DSH_HOME（默认当前用户 .dsh）下：my-fish-location.json 保存资料位置；my-fish-migration.json 保存未完成事务元数据。它们不包含凭据正文，不纳入 Git。

未提交失败继续使用源目录，已生成的目标副本保留；重试时请选择其他空位置。若仅收尾失败但定位已提交，恢复以新位置为准，不误切回旧数据。重启会检查未完成日志；归属或目录无法验证时停止写入并给出原因，避免静默新建空账号。

## 会话与权限

已有会话通过宿主 resolveAgent、runMaintenance 和 workingDirectory.set 同步实际 cwd；maintenance 期间用户新输入排队，迁移结束后继续，不启动额外模型请求。休眠会话重载后，仅纠正仍指向旧管理目录的 cwd，不覆盖用户自行切到其他无关目录的选择。

**DSH 的原始会话工作区头、项目归属与文件权限根不变。** 新路径上的命令或文件操作仍可能被宿主拒绝或要求审批。本插件不会自动开完全访问模式、篡改会话头或提权，也不把切换实际 cwd 宣称为迁移了宿主项目。

已有进程和终端的 cwd 不会随设置改变；迁移前应先停止相关任务。其他程序同时修改源文件会导致校验失败并保留源数据。

## 验证层级

迁移/恢复回归只使用临时合成文件；界面在离线页面核验。安装版隔离验证使用真实 WorkingDirectory、AgentLoop、Session/Projection 和 SandboxPolicy，确认同会话、maintenance 排他、事件重放与权限边界，没有读取真实个人资料或启动模型。最终结果见 VALIDATION.md。
